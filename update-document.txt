## FILES CREATED

### css/pages/rocket-theme.css
Brand new file. Contains ALL rocket experience CSS:
- Scroll snap: `html:has(.rocket-hull)` scopes snap to homepage only. `mandatory` on desktop, `proximity` on mobile (<=768px) to avoid trapping.
- `scroll-padding-top: var(--nav-height)` accounts for fixed navbar.
- `.rocket-section` class: `scroll-snap-align: start`, `min-height: 100dvh`.
- `.rocket-ambient` div: fixed, z-index -1, holds the scroll-linked gradient (JS overrides the static fallback).
- `.rocket-hull::before`: fixed hull panel texture — repeating linear gradients making 200x150px panels at 2% white opacity.
- Section dividers: `box-shadow: inset` on `.rocket-section + .rocket-section` for metallic joint line. `::after` pseudo for rivet dot pattern every 80px. Uses box-shadow instead of ::before to avoid conflict with `.cta-section::before` (which has its own radial glow).
- `.rocket-nav`: fixed right side, vertically centered. SVG rocket silhouette at 20% opacity (desktop only). 6 `<button>` dots with `data-section` attributes.
- `.rocket-nav-dot.active`: orange glow + pulse animation (`navDotPulse` keyframes).
- `.rocket-nav-label`: tooltip that slides in from right on hover. Uses backdrop-filter blur.
- Mobile (<=1024px): SVG silhouette hidden, dots shrink to 8px, active = 10px. No labels.
- Very small (<=380px): dots shrink further to 6px.
- `.cursor-glow`: 400px fixed radial gradient, `will-change: transform`, hidden by default (opacity 0), shown via `.visible` class. Hidden on `hover: none` (touch devices).
- `.rocket-ambient-static`: static version of the gradient for non-homepage pages.
- `prefers-reduced-motion`: disables snap, forces static gradient, hides cursor glow, kills pulse animation.

### js/rocket-experience.js
Brand new file. Contains ALL rocket experience JavaScript:
- Homepage-only guard: checks `window.location.pathname` and exits early on other pages.
- Checks `prefers-reduced-motion` before enabling animations.
- Scroll-linked ambient gradient: `requestAnimationFrame` throttled scroll listener. Interpolates between 6 color stops (one per section) using lerp. Updates `.rocket-ambient` background style directly.
- Section observer: `IntersectionObserver` with `rootMargin` offset for navbar height and `threshold: 0.3`. When a section enters view, it updates the active nav dot (adds/removes `.active` class) and sets `--navbar-accent` CSS variable on the navbar element.
- Nav click handlers: each `.rocket-nav-dot` button calls `scrollIntoView({ behavior: 'smooth' })` on its target section.
- Cursor glow: `mousemove` listener updates transform position. `mouseleave` hides it. Separate `IntersectionObserver` at `threshold: 0.5` updates the glow color per section. Disabled on touch devices (`'ontouchstart' in window`).

## HOW IT ALL CONNECTS

1. User loads homepage → `rocket-theme.css` enables scroll snap on `html` (via `:has(.rocket-hull)`).
2. Each `.rocket-section` snaps into place as user scrolls.
3. `rocket-experience.js` runs scroll listener → interpolates ambient gradient colors → updates `.rocket-ambient` background.
4. Same JS file runs `IntersectionObserver` → detects which section is visible → lights up the corresponding `.rocket-nav-dot` → sets `--navbar-accent` on the navbar.
5. Navbar's `::after` accent line picks up the color change via the CSS variable.
6. On desktop, cursor glow follows mouse and shifts color per section.
7. On other pages, only the static ambient gradient and enhanced navbar apply.

---

## IMPORTANT IMPLEMENTATION DETAILS

- Section dividers use `box-shadow: inset` instead of `::before` pseudo-elements because `.cta-section::before` already has a radial glow effect. Using box-shadow avoids the conflict.
- Scroll snap is scoped via `html:has(.rocket-hull)` — only index.html has `class="rocket-hull"` on its `<main>` element, so other pages are unaffected even though they load the same CSS.
- The JS file has an early return guard checking the page pathname, so it does nothing on non-homepage pages.
- The `IntersectionObserver` rootMargin reads `--nav-height` from CSS custom properties (fallback 72px) to offset the observation area below the fixed navbar.
- Cursor glow checks for `'ontouchstart' in window` AND uses `@media (hover: none)` in CSS as a double guard against showing on touch devices.

## THE ROCKET — VISUAL DESIGN

### What It Looks Like
Build a detailed, stylized rocket illustration using **pure SVG** (inline in the HTML, not an image file). This is not the small CSS rocket currently in the hero — this is a large, detailed, interactive rocket that serves as the site's central visual element.

**Rocket style:**
- Sleek, modern, slightly stylized — think technical blueprint meets premium illustration
- NOT cartoonish, NOT clipart, NOT realistic 3D — clean vector art with personality
- Dark metallic body with subtle gradients (dark grays, charcoal)
- Orange accent lines along segment borders and panel details
- Blue subtle glow effects on windows, engines, accent lights
- Each segment has visual details that hint at its content purpose:
  - **Nose Cone** (Hero/Launch): Pointed tip with a glowing orange tip, antenna array, "LaunchedOps" etched small on the hull
  - **Cockpit** (The Problem): Windshield/viewport windows with a subtle blue glow inside, instrument panel silhouette visible
  - **Cargo Bay** (What You Get): Large hull doors with panel lines, cargo indicator lights, wider body section
  - **Observation Deck** (Our Work/Portfolio): Row of illuminated windows showing faint screen-like glows inside, like you can see the work happening
  - **Engine Room** (How It Works): Exposed mechanical details, pipes, conduits, orange warning stripes, access panels

**Rocket dimensions:**
- Desktop: The rocket sits on the **left side** of the viewport, roughly 35-40% width, vertically spanning most of the visible screen height. Content sections appear on the **right side** (55-60% width).
- The rocket should be tall enough that all 6 segments are clearly visible and clickable without being cramped.

### Segment Interaction States
Each rocket segment has 3 visual states:

1. **Default:** Muted, darker tone. Subtle panel lines visible. Segment label faintly visible.
2. **Hover:** Segment brightens slightly. Orange accent lines glow. A tooltip/label appears showing the section name ("The Problem", "Cargo Bay", etc.). Cursor changes to pointer.
3. **Active (current section):** Segment fully illuminated. Orange border glow pulses subtly. Internal details light up (windows glow brighter, engine parts animate, etc.). The segment looks "powered on."

### Segment Labels
Each segment should have a small label that appears on hover:

- Cockpit → "The Problem"
- Cargo Bay → "What You Get"

Labels should appear as sleek tooltips — dark background, white text, slight backdrop blur, positioned just to the right of the rocket (or above on mobile). Animate in with a subtle fade + slide.

## THE NAVIGATION EXPERIENCE

### How It Works — Desktop

**Layout:** Split-screen. Rocket fixed on the left (~35-40% viewport width). Content panels on the right (~55-60% viewport width). The content area is the scrollable/navigable zone.

**Two ways to navigate:**

1. **Click a rocket segment** → The content panel smoothly transitions to that section. The clicked segment lights up. Other segments dim. The transition should feel like you're "entering" that part of the rocket — maybe the content slides in from the right, or fades in with a slight zoom, or the rocket segment visually "opens" to reveal the content.

2. **Scroll normally** → As the user scrolls through the content on the right side, the rocket on the left tracks their position. The corresponding segment lights up as each section enters the viewport. This is the fallback for people who just want to scroll like a normal website.

**Content transitions:**
When clicking a rocket segment (not scrolling), the transition between sections should feel intentional and designed:
- The current content fades out slightly (opacity drop + subtle scale down)
- A brief transition moment (150-250ms)
- The new content fades in (opacity up + subtle slide from bottom or right)
- The rocket segment animates to its "active" state simultaneously
- Keep it fast — this should feel snappy, not slow. If the animations feel sluggish, the experience is ruined.

**Scroll behavior:**
When scrolling (not clicking), use scroll snap on the content sections so they settle cleanly into view. The rocket segment highlight follows via IntersectionObserver (similar to what's already implemented, but now updating the SVG rocket segments instead of just dots).

### How It Works — Tablet (769-1024px)

**Layout:** The rocket moves to a **horizontal orientation across the top** of the page, below the fixed navbar. It becomes a horizontal bar/strip showing the rocket from nose (left) to exhaust (right). Each segment is still clickable and shows hover states. Think of it like a visual progress bar shaped like a rocket.

Content sections stack below and scroll normally. The horizontal rocket bar stays fixed and highlights the current segment as you scroll.

**Dimensions:** The horizontal rocket strip should be roughly 60-70px tall, spanning the full viewport width. Segments are evenly distributed.

### How It Works — Mobile (0-768px)

**Layout:** The full interactive rocket is **not shown on mobile**. Instead, use a compact **rocket segment indicator** — a small vertical or horizontal strip of 6 dots/segments (similar to the existing rocket-nav dots but with more visual identity). Each dot is shaped like a mini section of a rocket (pointed top dot, wider middle dots, nozzle-shaped bottom dot) rather than plain circles.

Content sections stack and scroll normally (proximity scroll snap, not mandatory — don't trap users). The mini rocket nav sits fixed on the right edge of the screen.

Alternatively: show a simplified mini rocket silhouette (much smaller, ~40-50px tall) fixed on the right side, with each segment still tappable. Keep it subtle enough to not block content.

**CRITICAL:** Mobile must still be fully functional and look great even without the big interactive rocket. The content and CTAs are the priority on mobile. The rocket experience is a desktop/tablet enhancement.

## JAVASCRIPT ARCHITECTURE

### New File: js/rocket-nav.js
This file handles the new rocket navigation experience. It should REPLACE the functionality in `js/rocket-experience.js` (the dot nav, ambient gradient, cursor glow section tracking) but reuse the same patterns and concepts. Don't delete rocket-experience.js — keep it as a fallback or reference — but the new file takes over.

**What this file does:**

5. **Hover handlers:**
   - Mouseenter on a segment: add `--hover` class, show label tooltip

6. **Ambient gradient:** Port the existing scroll-linked gradient interpolation from rocket-experience.js
7. **Cursor glow:** Port the existing cursor glow tracking from rocket-experience.js
8. **Resize handler:** Debounced resize listener that adjusts rocket layout if needed (desktop ↔ tablet ↔ mobile breakpoints)

function navigateToSection(targetId) {
  const currentSection = getCurrentActiveSection()
  const targetSection = document.getElementById(targetId)

  currentSection.classList.add('section-exiting')

}

## PERFORMANCE & ACCESSIBILITY

### Performance
- The SVG rocket must be optimized — no bloated paths, no unnecessary groups
- All animations use `transform` and `opacity` only (GPU-accelerated, no layout thrashing)
- Content transitions should be fast (under 300ms total) — snappy, not sluggish
- The split layout should not cause Content Layout Shift (CLS)
- Lazy load any heavy elements below the fold
- Test: everything should run at 60fps on a mid-range phone

### Accessibility
- Every rocket segment must have `role="button"`, `tabindex="0"`, and descriptive `aria-label`
- Keyboard navigation: Tab through segments, Enter/Space to activate
- Screen readers should announce: "Navigate to [section name]" on each segment
- `prefers-reduced-motion`: disable all animations, transitions, and fancy effects. Fall back to instant section jumps with no animation. The rocket still shows and segments still highlight, but nothing moves.
- The content must be fully accessible without JavaScript — if JS fails, the page should still be a normal scrollable page with all content visible
- Color contrast: all text must meet WCAG AA (4.5:1 for body, 3:1 for large text)
- Focus indicators: visible focus ring on all interactive elements including rocket segments

### Fallback / Progressive Enhancement
- **No JS:** Page renders as a normal scrollable page. Rocket SVG shows as a static illustration. All content is visible and accessible.
- **Reduced motion:** No animations, instant transitions, static highlights
- **Small screens:** Simplified nav, no split layout, scroll-based experience
- **Old browsers:** If CSS grid or IntersectionObserver aren't supported, fall back to a simple stacked layout
